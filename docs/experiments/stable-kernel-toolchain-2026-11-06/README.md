# Stable numeric backend exploration

These artifacts preserve the original exploratory candidate and its measurements. The backend was later approved for integration in `liq-docs/plans/rust-stable-backend-migration-oracle-decision-2026-11-06.md`; the integrated comparison is recorded in `integrated-smoke-receipt.md`. The benchmark and arithmetic parity checks use no market data. The separately authorized true-range smoke check is described in its receipt. No strategy, signal or financial backtest was run.

- Repository revision: `613f4e8f05ff4c1c27d286511ee769f20b7c4272`; baseline `crates/liq-ta/src/kernels/simd.rs` SHA-256 `a5793c4c4f78a9ed1b778415e60db8e427987bc9ad1974f6816df26649e04788`.
- Workspace Cargo.lock SHA-256: `ab682a4b1bb22b5b735e9deb271f8bd02016befdc6b5dc8d2d7ec9d8005d86a8`; the standalone driver resolved its own lock, preserved here.
- Baseline compiler: `rustc 1.99.0-nightly (be8e82435 2026-07-11)`; candidate: `rustc 1.98.1 (48a229cea 2026-09-01)`. Host: Apple M4 Max, `aarch64-apple-darwin`.
- Cargo release profile: `opt-level=3`, `lto=fat`, `codegen-units=1`, `panic=abort`, `strip=true`; default target and features, no PGO.
- `candidate.patch.gz` preserves the original patch byte for byte; decompress it and place `scalar_backend.rs` under `crates/liq-ta/src/kernels/simd/` to reproduce the prototype in a scratch checkout. This is not an approved production patch.
- Driver: standalone Cargo package depending on the baseline or candidate `crates/liq-ta` by local path. Copy `benchmark.rs` or `parity.rs` to its `src/main.rs`, preserve this package's `Cargo.lock`, use the release profile above, then run `cargo +nightly run --release --offline --locked` for baseline or `cargo +1.98.1 run --release --offline --locked` for candidate.
- Arithmetic input: 131,072 values derived from integer residues, 3,000 repetitions per observation, three sequential observations. All components of the finite-reduction tuple are consumed. This is a microbenchmark, not representative market-data or deployment evidence.
- In the recorded sample, sum took 112–113 ms baseline versus 85–88 ms candidate; dot product 120–213 ms versus 139–140 ms; finite sum/squares/count 186–209 ms versus 278–279 ms. The noisy, single-machine observations establish neither fleet-wide effects nor statistical significance.
- `parity.rs` compares selected f64 kernels for lengths 0–65 across finite, NaN, infinity, cancellation, signed zero and small-magnitude inputs. Non-NaN bit patterns and NaN classification match; the driver canonicalizes NaNs and does not compare their payloads or signs. The logged outputs have identical SHA-256 before compression (`8bf412183c972a731bd288177de054c0803910833a9190e53b10e4cb5f1a942e`). These cases do not establish full numeric equivalence or cover true range.
- The original scratch candidate ran 44 existing arithmetic-kernel tests on each of Rust 1.95.0 and 1.98.1 and emitted unused-method warnings. Those unused methods were removed during integration; the integrated implementation subsequently passed the configured Clippy check.
- `parity_f32.rs` runs 396 corresponding f32 cases, comparing sums, extrema and lagged subtraction. Non-NaN bit patterns and NaN classification match; NaN payloads and signs are not compared. The compressed outputs are retained.
- The final Rust workspace coverage run measured 94.27% line coverage. The `coverage/` directory preserves its report, test output and diagnostics. LLVM reported 24 repeated mismatched mappings for one inline MFI helper; the independent analysis and conservative coverage calculation are recorded in `liq-docs/plans/rust-coverage-mapping-warning-oracle-decision-2026-11-06.md`. Branch and Python-source coverage were not measured.
